17-5 定时器

JavaScript 的两种定时器

setTimeout 延时执行一次，setInterval 每隔一段时间重复执行。 两者都由浏览器提供、返回一个数字 ID，分别用 clearTimeout 与 clearInterval 取消。 下面两个面板可以直接操作，观察实际执行时间与 ID 的变化。

setTimeout · 延时执行一次

时间到后执行一次回调，然后自动结束
尚未启动定时器
// 延时 2000 毫秒后执行一次
var sc_id = setTimeout(function () {
    console.log("时间到，执行回调");
}, 2000);

// 需要提前停止时：
clearTimeout(sc_id);

setInterval · 周期重复执行

每隔固定时间执行一次，直到被清除
00:00.0
已执行 0 次回调 · 定时器 ID：—
尚未启动定时器
// 每 100 毫秒执行一次
var sc_id = setInterval(function () {
    console.log("每 100ms 执行一次");
}, 100);

// 必须手动清除，否则会一直执行
clearInterval(sc_id);

两种定时器的区别

对比项 setTimeout setInterval
执行次数 只执行一次 每隔固定时间重复执行
返回值 数字 ID，用于 clearTimeout(id) 数字 ID，用于 clearInterval(id)
是否自动结束 执行完回调后自动结束 不会自己停，必须调用清除方法
典型场景 延迟提示、防抖、动画、轮询一次 时钟、倒计时、轮播、周期性刷新
注意点 实际延时 ≥ 设定值，主线程忙碌时会推迟 回调耗时较长时，执行间隔会被压缩，可改用递归 setTimeout

使用要点

  • 定时器函数是异步的：代码不会停在那里等，而是先继续往下执行，时间到了才回到回调。
  • 返回的 ID 只是浏览器内部的编号，清除时用 clearTimeout 或 clearInterval，传错方法在部分浏览器仍能生效，但规范不保证，应按对应关系使用。
  • 页面关闭或组件卸载时要记得清除，否则回调可能操作已经不存在的元素。
  • 需要「上一次执行完再等一段时间」的精确间隔时，用递归 setTimeout 代替 setInterval。
